# 听写链路性能与可靠性治理闭环

## 背景与范围

用户在真实听写中报告三类问题：原始上屏没有标点、partial 反复闪动、停止后校对常显示
`0/1` 且未实际替换。运行日志还记录过 ChatGPT 输入目标无法安全恢复。

本轮只优化本地离线听写链路：采集、流式识别、文本注入、目标恢复、停止后校对和其可观测性。
不更换模型、不引入联网服务、不修改一键安装路径；保留用户本地 `config.json`。

## 已知事实与假设

- 79 字用户样例在本机 Qwen3-1.7B 上实际校对约 9.25 秒，并返回带标点的文本。
- 现有代码在校对已经完成后才判断总耗时，超过 10 秒会丢弃已经得到的结果，因此没有缩短等待却可能导致 `0/1`。
- sherpa partial 是累计假设，但主要改动通常在尾部；每次全文删除重输会造成肉眼可见闪动。
- ChatGPT 桌面端的 WebView UIA 节点可能随界面重绘变化；必须先验证初始可编辑性，且不能放宽窗口/原生焦点身份约束。
- 基线固定为提交 `17a3eb8`；候选实现明确为本工作树。比较必须在临时 worktree 或明确的
  Git 状态中执行，不能把已有工作区改动误称为基线。

## 成功标准

| 维度 | 指标 | 验收方法 |
|---|---|---|
| 流式体验 | 稳定前缀不回写；未稳定尾部允许修正；无重复、无漏字 | 可见回放序列 + 隔离编辑框回归 + 手工 60 秒连续听写 |
| 校对可靠性 | 模型返回结果后会说明并实际应用；失败原因可区分、总数守恒 | 固定文本 stub 回归 + 用户样例真实模型复现 |
| 标点质量 | 长中文样例有内部标点；兜底句末符号单列统计，不算校对成功 | Proofreader 真实模型与单元回归 |
| 焦点安全 | ChatGPT 仅忽略 volatile UIA RuntimeId，窗口/进程/线程/原生焦点仍锁定 | UIA 重绘、Tab 切换、鼠标点击、窗口关闭的正反回归与真机冒烟 |
| 可观测性 | 分别得到 ASR、上屏、目标恢复、校对与替换耗时/失败计数 | 固定 schema 的 JSON 报告、运行命令和环境指纹 |
| 活性 | 校对较慢可告警并完成；卡死时在规定期限释放会话与焦点 | hanging stub 回归 + 取消后的迟到结果拦截 |
| 回归 | 项目机械检查和相关桌面测试全部通过 | `python scripts/check_all.py --quiet` + 目标测试 |

## 执行阶段

### 1. 基线与观测

1. 为每次会话增加仅本地的性能事件采集：`perf_counter_ns` 写入有界 ring buffer，结束时
   批量导出。热路径禁止逐事件打印、文件写入或额外锁竞争。
2. 固定 JSON schema：环境指纹（Python、模型 SHA256、llama/sherpa 版本、`n_threads`、
   warm/cold）、时钟来源、样本数、每段耗时、失败计数与仪器化状态。
3. 新增固定输入性能脚本：短句、用户 79 字样例、连续 partial 修正序列；partial/注入至少
   30 次、真实校对至少 10 次。样本不足时明确不报告 P95。
4. 在临时 worktree 的 `17a3eb8` 与候选工作树分别执行，形成同格式对照；另外测量仪器开关
   的差值，P95 额外开销预算不超过每事件 1ms。

验收：报告可重复生成，不触碰用户应用、不写真实配置、不加载麦克风；每次报告都可追溯
比较的 Git 状态与运行环境。

### 2. 上屏路径

1. 明确产品语义：已确认的稳定前缀只增不改；识别仍会修正的尾部可退格重写，避免重复和
   错乱。若实测仍闪动，改为延迟显示不稳定尾字，不把整句刷新作为默认降级。
2. 只替换 partial 的变化尾部，保留最长公共前缀。
3. 为前缀缩短、完全替换、空 partial、Unicode/中英空格边界、连续尾部回退、删除与插入
   之间失焦和输入失败补回归。
3. 用隔离编辑框验证屏幕文本与记账一致。

验收：不出现全文清空式闪动；最终文本精确一致；焦点失效时仍立即关闸。

### 3. 校对路径

1. 10 秒作为 soft SLA：完成后仍应用并报告“较慢”。30 秒为逻辑会话上限：释放目标焦点并
   阻断迟到写入。llama-cpp 当前调用不可在线程内强杀，超时后的模型线程会后台收尾；后续若
   需要终止计算，改为隔离子进程并测量冷启动代价。hanging stub 必须证明会话可安全取消。
2. 把模型清理和只加标点分开：清理失败时从原文降级到只加标点；两次模型失败时仅补
   句末符号，不改写识别内容。
3. 日志分开统计 `cleanup_success`、`punctuation_model_success`、`terminal_fallback`、
   `模型未返回`、`替换失败`、`已优化`、`无需修改`；所有块计数必须与总块数守恒。

验收：固定长中文样例有内部标点且正确应用；慢校对回归证明结果不再被事后超时丢弃；
纯数字、URL、文件路径和非中文文本不会被错误追加中文句号；卡死 stub 证明可恢复。

### 4. 目标兼容与真机验收

1. ChatGPT 初始捕获仍要求可编辑控件；白名单限定可执行文件名、窗口类与实测版本。会话期间
   只忽略该应用 volatile RuntimeId，仍核对窗口、进程、线程和原生焦点句柄。
2. 回归覆盖 RuntimeId 重绘仍能写入，及同 HWND 内 Tab 切换、鼠标点击、窗口关闭均立即关闸。
3. 依次在记事本、ChatGPT、OpenCode 进行短句和连续句验证；记录真实目标中断时的具体身份
   变化，未证实前不扩大兼容名单。

验收：三种目标均能上屏与校对；切走、关闭或手动编辑时不向错误位置写入。

### 5. 独立审查、沉淀与提交

1. 独立审查重点检查性能测量是否干扰热路径、尾部替换是否破坏记账、标点兜底是否篡改
   原意、ChatGPT 白名单是否过宽。
2. 逐条修复审查问题并复跑全部验证。
3. 同步更新 overview、bugfix 档案、CURRENT、CHANGELOG 与记忆索引，提交时排除 `config.json`。

## 风险与决策边界

- 不采用“停止前完全不显示文字”的降级策略，除非实测尾部替换仍无法消除闪动。
- 不把校对时间阈值当作事后丢弃条件；如需真正的硬超时，必须能取消本地推理后再实施。
- 不因 ChatGPT 的 UIA 重绘取消输入安全校验；只在已捕获、已验证的特定应用上移除不稳定的
  RuntimeId 比对。
- 1.7B 模型仍可能产生同音字，性能闭环不把语言质量问题伪装成性能修复。

## 当前状态

- 阶段 1 基线已完成：固定 `17a3eb8` 与候选实现各跑 30 次 partial、10 次短中文与
  长中文真实本地校对。候选把模拟注入字符从 1,290 降至 510、退格从 960 降至 180；
  长样例校对中位 2.770 秒（基线 2.769 秒），采样器 1,000 次记录 P95 低于 0.001ms。
- 阶段 2、3 的实现及 regression 已完成：慢结果应用、中文标点兜底分类、30 秒逻辑会话
  上限及迟到写入阻断均有隔离回归。
- 独立计划审查已完成并据此增加固定基线、采样预算、结果分类、硬超时和 ChatGPT 白名单
  收紧项。阶段 4 的 ChatGPT/OpenCode 真机冒烟仍需用户环境完成；隔离桌面脚本受当前
  Windows 前台切换策略阻断，未作为通过证据。
