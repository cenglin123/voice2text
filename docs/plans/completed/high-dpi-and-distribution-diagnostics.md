# 高 DPI 界面与分发端诊断

## 验收目标

1. Windows 系统缩放为 150%/200% 时，悬浮窗、设置窗和托盘菜单在屏幕上的逻辑尺寸与 100% 接近；悬浮窗拖拽尺寸仍以设置页的 50%~150% 用户倍率记账。
2. 托盘图标在深浅任务栏上都能辨认，状态色与当前行为一致。
3. 分发 ZIP 包含面向 agent 的排查说明、干净源码基线与反馈导出脚本。分发端修改源码后能生成不依赖 Git 的 Markdown 反馈与统一 diff；工具默认不采集配置、录音或日志正文。

## 实现边界

- 沿用现有 system-DPI-aware 进程模式，依据系统 DPI 缩放应用自行绘制的像素内容；不切换到需要处理每次屏幕迁移事件的 per-monitor 模式。
- 托盘图标使用深色底与状态色麦克风，避免按系统颜色猜测主题。
- 分发端使用独立的 `AGENTS.md`，只定义排查边界、验证与反馈交付。开发仓库的治理文档依赖 Git 历史、记忆索引与模型来源，不适合直接复制给安装用户。
- 分发基线只包含白名单中的可编辑源码与脚本，不包含配置、模型、运行时或个人数据。

## 验证

- 100%/150%/200% 的窗口和交互区域尺寸回归；设置页截图检查裁切与页脚；16/20/24px 托盘图标在亮暗背景上检查对比。
- `scripts/check_release.py` 对发行指南、基线与反馈导出进行临时 ZIP 回归；导出后核对 Markdown 和 diff 不含用户路径或配置。
- 运行项目要求的 `python scripts/check_all.py --quiet`，再构建候选 ZIP，检查摘要与归档内容。

- `scripts/check_release.py`、`python scripts/check_all.py --quiet` 通过；0.1.4 候选 ZIP 已重建，
  CRC、摘要、发行指南、反馈工具与基线范围均已验证。
